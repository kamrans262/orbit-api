ORBIT PRESENCE + LOCATION PRIVACY MODULE
========================================

Copy/merge the top-level orbit_api folder into:
C:\laravel-projects\orbit_api

Then run:

php artisan migrate
php artisan optimize:clear
vendor\bin\pint
vendor\bin\pint --test
php artisan test
php artisan route:list --path=api/v1/presence
php artisan route:list --path=api/v1/circles

NEW API ROUTES
--------------
PUT   /api/v1/presence
GET   /api/v1/presence/me
PATCH /api/v1/presence/settings
GET   /api/v1/circles/{circleId}/presence
GET   /api/v1/circles/{circleId}/members/{membershipId}/presence

All routes require Sanctum authentication.

PRESENCE UPDATE BODY EXAMPLE
----------------------------
{
  "device_id": "optional-registered-device-uuid",
  "status": "online",
  "latitude": 31.5204567,
  "longitude": 74.3587123,
  "accuracy_meters": 8.5,
  "battery_level": 72,
  "is_charging": false,
  "network_type": "wifi",
  "movement_type": "walking"
}

Allowed status values:
online, idle, offline

Allowed network values:
wifi, cellular, ethernet, offline, unknown

Allowed movement values:
stationary, walking, running, cycling, driving, transit, unknown

PRIVACY RULES
-------------
precise:
- exact current/latest coordinates may be returned
- accuracy may be returned

approximate:
- coordinates are reduced to neighborhood-level precision
- exact accuracy is not returned

hidden:
- coordinates are never returned
- movement is hidden
- non-location presence metadata can still be shown

ghost:
- status becomes "ghost"
- coordinates and last-known location timestamps are never returned
- movement, battery, network and last-seen metadata are hidden

Global Ghost Mode overrides every Circle setting. Enabling it also clears the
current server-side latitude, longitude, accuracy and movement fields so stale
coordinates cannot accidentally be exposed. Disabling Ghost Mode does not
restore old coordinates; the device must report a new location.

Circle-specific privacy remains controlled through the existing endpoint:
PATCH /api/v1/circles/{circleId}/members/{membershipId}
with location_mode: precise | approximate | hidden | ghost

NOTES FOR LATER PRODUCTION SCALE
--------------------------------
This module intentionally stores the latest durable presence state in MySQL for
localhost/development and a simple production v1. The public API and privacy
logic are separated from storage so hot current-presence state can later move
to Redis/WebSocket infrastructure without changing Flutter's API contract.

The module does not create historical location tracking yet. That belongs in a
separate location-history/geofencing milestone with retention rules.
